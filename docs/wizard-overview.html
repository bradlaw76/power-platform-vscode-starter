✦GitHub Copilot's Role in This Wizard

Copilot is the primary interface for running this wizard — not just a code helper

🧙 Discovery Facilitator
Copilot Chat runs the planning wizard interactively — asking one discovery question at a time, explaining unfamiliar concepts (PAC CLI, Dataverse, solutions), and guiding you through the 13-question sequence before any build scripts run.
📄 Artifact Generator
After collecting answers, Copilot scaffolds spec.md, plan.md, tasks.md, and answers.md — mapping entity names, applying publisher prefixes, and structuring the Spec Kit planning files that gate every build.
🔁 Retrofit Handler
For mid-project work, Copilot reverse-engineers your current state — asking what tables, forms, and flows already exist — then generates a spec that reflects reality and a plan covering only what remains.
🛡️ Planning Gate Enforcer
Copilot enforces the hard rule: build scripts do not run until spec.md and plan.md are reviewed. It will not suggest running scripts 20–62 before planning is approved.
🧪 Script Companion
During the build sequence, Copilot explains each script's purpose, surfaces validation checkpoints, interprets PAC CLI output, and helps diagnose failures — acting as a pair programmer familiar with every step of the bootstrap sequence.
📚 Skill-Powered Context
The repo-shared power-platform-wizard-init skill is the primary Copilot entry point. It selects a chat or terminal route, enforces the planning gate, and reads existing progress telemetry. The optional power-platform-vscode-wizard Claude skill remains available after running 01-install-skills.ps1.
How to invoke it: Open GitHub Copilot Chat in VS Code and run /power-platform-wizard-init for the primary guided start. It lets you choose chat or terminal intake and can monitor progress. Direct alternatives remain supported: /power-platform-demo-wizard for chat-first intake, or pwsh ./scripts/bootstrap/05-start-wizard.ps1 for terminal intake. 3 Metrics & Telemetry Tracked

The wizard emits telemetry events to .wizard-metrics/events.jsonl throughout the build sequence. Scripts 81 and 82 consume these events to produce a progress matrix and an HTML dashboard. All telemetry is local — nothing is sent to external services.
