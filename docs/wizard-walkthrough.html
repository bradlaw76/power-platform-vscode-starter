Power Platform VS Code Starter Walkthrough

This page is the end-to-end, clickable runbook for starting with the shared skill, completing planning gates, executing bootstrap scripts in order, and tracking run progress.

Authoritative sequence: onboarding Primary entry: /power-platform-wizard-init Direct wizard paths still supported

Start Paths

Primary path: shared skill Run /power-platform-wizard-init in Copilot Chat to choose chat or terminal flow and monitor progress.
Direct chat path Run /power-platform-demo-wizard to jump directly into discovery prompts.
Direct terminal path Run pwsh ./scripts/bootstrap/05-start-wizard.ps1 for a new build or add -Retrofit for existing work. Both paths generate report-mappings.md and block unmapped critical report tables.

Full Walkthrough

0 Clone and open the repo foundation
git clone https://github.com/bradlaw76/power-platform-vscode-starter cd power-platform-vscode-starter code .
  • Confirm you can see docs, scripts, payloads, and requirements folders.
  • Reference: docs/onboarding.md
1 Install extensions and prerequisites tooling
pwsh ./scripts/bootstrap/00-prereq-check.ps1
  • All prerequisite checks should pass before you continue.
  • Script: scripts/bootstrap/00-prereq-check.ps1
2 Optional one-time Claude skill install optional
pwsh ./scripts/bootstrap/01-install-skills.ps1
  • This installs the Claude skill set to your local machine profile.
  • The shared Copilot skill works from the repo without running this.
  • Script: scripts/bootstrap/01-install-skills.ps1
3 Start intake with the primary shared skill primary
/power-platform-wizard-init
  • Use this to choose chat or terminal route while preserving the same gate checks.
  • Alternative chat path: /power-platform-demo-wizard
  • Alternative terminal path: pwsh ./scripts/bootstrap/05-start-wizard.ps1
  • Scripts and skill links: 05-start-wizard.ps1, shared skill
4 Complete discovery and planning gate required
  • Answer all required discovery prompts.
  • Create or refine spec, plan, and tasks files before build scripts.
  • Contract sources: docs/wizard-contract-v1.md, wizard.profile.json
Do not run scripts 20 and above until planning files are complete and aligned.
5 Generate demo script artifacts recommended
pwsh ./scripts/bootstrap/06-demo-script-wizard.ps1 -ScenarioSlug <scenario-slug> pwsh ./scripts/bootstrap/07-demo-dry-run.ps1 -ScenarioSlug <scenario-slug>
  • These generate walkthrough and talk-track files under your scenario folder.
  • Scripts: 06-demo-script-wizard.ps1, 07-demo-dry-run.ps1
6 Authenticate and bind environment settings required
pwsh ./scripts/bootstrap/10-auth-connect.ps1
  • Confirm az account and PAC profile are active after this step.
  • Script: 10-auth-connect.ps1
7 Validate and execute build scripts in sequence core execution
pwsh ./scripts/bootstrap/15-dry-validate.ps1 pwsh ./scripts/bootstrap/20-build-tables.ps1 pwsh ./scripts/bootstrap/30-build-columns.ps1 pwsh ./scripts/bootstrap/40-build-relationships.ps1 pwsh ./scripts/bootstrap/50-add-to-solution.ps1 pwsh ./scripts/bootstrap/55-build-business-process-flows.ps1 -ScenarioSlug <scenario-slug> pwsh ./scripts/bootstrap/60-build-forms-views.ps1 pwsh ./scripts/bootstrap/62-build-app-module.ps1 -ScenarioSlug <scenario-slug> pwsh ./scripts/bootstrap/70-build-web-resources.ps1 -ScenarioSlug <scenario-slug> # optional pwsh ./scripts/bootstrap/80-post-build-analysis.ps1 -ScenarioSlug <scenario-slug>
  • Run each script only after the previous step exits cleanly.
  • If solution contamination appears at step 50, use the isolation runbook.
  • For step 55, apply mandatory BPF reliability gates: explicit stage and branch design, deterministic validation PASS thresholds, and verified app linkage (workflow component type 29) before declaring done.
  • Runbook: docs/solution-isolation-runbook.md
  • BPF runbook: docs/bpf-operator-runbook.md
8 Monitor wizard progress from telemetry visibility
pwsh ./scripts/bootstrap/81-build-progress-matrix.ps1 pwsh ./scripts/bootstrap/82-build-progress-report.ps1
  • Event log: .wizard-metrics/events.jsonl
  • Matrix output: .wizard-metrics/build-progress-matrix.md
  • HTML report: .wizard-metrics/build-progress-report.html
  • Set WIZARD_METRICS_OPTOUT=1 to disable telemetry for the current session.
9 Verify in Maker portal, export, unpack, commit, import release path
pac solution export --name "SOLUTION_NAME" --path "./out/SOLUTION_NAME_unmanaged.zip" --managed false pac solution unpack --zipfile "./out/SOLUTION_NAME_unmanaged.zip" --folder "./solutions/SOLUTION_NAME" --packagetype Unmanaged # commit on your branch git checkout -b feature/<short-description> git add . git commit -m "Add solution updates" git push -u origin feature/<short-description> # repack and import pac solution pack --zipfile "./out/SOLUTION_NAME_unmanaged_new.zip" --folder "./solutions/SOLUTION_NAME" --packagetype Unmanaged pac solution import --path "./out/SOLUTION_NAME_unmanaged_new.zip"
10 Record outcomes and submit feedback closeout
pwsh ./scripts/bootstrap/83-submit-feedback.ps1 -ScenarioSlug <scenario-slug>
  • Document results in the build log template.
  • Build log: docs/build-log.md
  • Feedback script: 83-submit-feedback.ps1
